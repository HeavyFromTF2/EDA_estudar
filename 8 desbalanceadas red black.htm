Sebenta Completa: Aula 8 — Árvores Red-Black

Pesquisa Binária Balanceada, Propriedades Estritas, Rotações e Casos de Ajuste · IPBeja

Porquê Árvores Red-Black? (Slide 2)

As operações básicas numa Árvore de Pesquisa Binária normal demoram O(h), onde h é a altura. Se os dados forem inseridos ordenados, a árvore degenera numa lista ligada gigante com h = n, estragando a eficiência. As árvores **Red-Black** resolvem isto forçando um balanceamento através de atribuição de cores, ganhando tempo O(log n) no pior cenário possível.

As 5 Propriedades Invioláveis (Slide 4)

Uma árvore de pesquisa binária é uma Árvore Red-Black se satisfizer as seguintes propriedades:

1. Cada nó é obrigatoriamente ou RED (Vermelho) ou BLACK (Preto).
2. A Raiz da árvore é sempre BLACK.
3. Todas as folhas vazias (NIL) são sempre BLACK.
4. Se um nó é RED, os seus dois nós filhos têm de ser obrigatoriamente BLACK (Não pode haver dois vermelhos consecutivos verticalmente).
5. Para cada nó, todos os caminhos simples desse nó até às folhas descendentas contêm exatamente o mesmo número de nós BLACK (Altura Negra - black-height).

O Slide 5 demonstra matematicamente que uma árvore red-black com n nós internos tem uma altura máxima de h <= 2 log(n + 1).

Como Funcionam as Rotações Locais (Slides 6-7)

Quando inserimos ou removemos nós, as propriedades Red-Black podem ser violadas. Para as corrigir, usamos Rotações. Elas alteram a estrutura de ponteiros em tempo constante O(1) sem alterar a propriedade de pesquisa binária (tudo à esquerda continua menor, tudo à direita continua maior).

A Intuição Visual da Rotação à Esquerda (LEFT-ROTATE):
Imagina o nó x e o seu filho direito y. Na rotação à esquerda, x desce para a esquerda, tornando-se filho de y. Como y assume o topo, a antiga subárvore esquerda de y (os nós intermédios) é adotada por x como o seu novo filho direito.

Esquema de Transformação Visual (Preservação de Ordem: A < x < B < y < C)

       Pai [x]                            Pai [y]
      /       \       LEFT-ROTATE(T,x)   /       \
   [A]         [y]    ===============> [x]        [C]
              /   \                   /   \
            [B]   [C]               [A]   [B]

Demonstração Controlada Interativa (Passos da Rotação)

Pseudocódigo Totalmente Comentado: LEFT-ROTATE(T, x) (Slide 7)

1y = x.right// Define o ponteiro y como o filho direito de x.
2x.right = y.left// Transfere a subárvore esquerda de y para a direita de x.
3if y.left != T.nil// Se a subárvore esquerda de y existir e não for sentinela...
4 y.left.p = x// ...atualiza o pai daquela subárvore apontando-o de volta para x.
5y.p = x.p// O nó y assume o ponteiro de pai que pertencia a x.
6if x.p == T.nil// Se x era o topo máximo absoluto (raiz da árvore)...
7 T.root = y// ...y passa a ser designado como a nova raiz oficial.
8else if x == x.p.left// Caso contrário, se x era filho esquerdo do seu pai...
9 x.p.left = y// ...atualiza o pai superior para apontar y à esquerda.
10else x.p.right = y// Se era filho direito, atualiza o pai superior para a direita.
11y.left = x// Liga x como o novo filho esquerdo de y.
12x.p = y// Define o pai de x como sendo o nó y.

Pseudocódigo Totalmente Comentado: RIGHT-ROTATE(T, y) (Slide 6)

1x = y.left// Define o ponteiro x como o filho esquerdo de y.
2y.left = x.right// Transfere a subárvore direita de x para o braço esquerdo de y.
3if x.right != T.nil// Se a subárvore direita de x existir de facto...
4 x.right.p = y// ...vincula o pai dessa subárvore de volta a y.
5x.p = y.p// O nó x herda a referência de pai superior de y.
6if y.p == T.nil// Se y era a raiz máxima absoluta da árvore...
7 T.root = x// ...x assume o estatuto de nova raiz da árvore.
8else if y == y.p.right// Se y era o filho direito do seu pai...
9 y.p.right = x// ...redireciona esse pai superior para x à direita.
10else y.p.left = x// Se era filho esquerdo, redireciona esse pai à esquerda.
11x.right = y// Transforma y no filho direito do recém-subido x.
12y.p = x// Fecha a amarração definindo o pai de y como x.

A rotação RIGHT-ROTATE(T, y) funciona exatamente de forma simétrica à anterior (Slide 6), invertendo as referências de esquerda e direita.

Inserção Dinâmica: RB-INSERT(T, z) (Slide 10)

Todo o nó entra na árvore pintado como RED (Vermelho). Se o pai desse novo nó também for RED, cria-se um conflito imediato: dois vermelhos seguidos (Violação da Propriedade 4). Para resolver, o algoritmo olha para a cor do TIO do nó atual z.

Caso 1: O Tio de z é RED (Inversão de Cores - Slide 12)

Cenário: Tanto o pai como o tio de z são vermelhos. É preciso diluir a cor vermelha.

Resolução: Não fazemos rotações. Apenas recolorimos: o Pai e o Tio passam a BLACK, e o Avô passa a RED. Como o Avô agora ficou vermelho, o ponteiro z sobe para o avô (z = z.p.p) para verificar se ele não entrou em conflito com o bisavô no ciclo while.

        [Avô Negro]                 [Avô Vermelho] (Novo z)
       /           \               /            \
  [Pai Vermelho] [Tio Vermelho] => [Pai Negro]  [Tio Negro]
        |                               |
    (Nó z)                            (Nó z)

Caso 2: O Tio de z é BLACK e z faz um "Ziguezague" (Slide 13)

Cenário: O tio é preto e os nós estão desalinhados (ex: o Pai é filho esquerdo do Avô, mas o z é filho direito do Pai).

Resolução: Fazemos imediatamente uma LEFT-ROTATE(T, z.p) no pai de z. Isto alinha os nós deslocando o conflito para baixo, transformando o cenário de forma automática no **Caso 3**.

Caso 3: O Tio de z é BLACK e z está em "Linha Reta" (Slide 14)

Cenário: O tio é preto e os nós estão todos alinhados em linha reta (ex: Pai é filho esquerdo do Avô, e z também é filho esquerdo do Pai). A árvore está muito pesada deste lado.

Resolução: Pintamos o Pai como BLACK, o Avô como RED, e aplicamos uma RIGHT-ROTATE(T, z.p.p) no Avô. A árvore faz um efeito de balança e equilibra ambos os lados. O loop termina aqui porque o pai agora é preto.

          [Avô Vermelho]               [Pai Negro]
           /          \               /           \
     [Pai Negro]    [Tio Negro] => (Nó z)     [Avô Vermelho]
       /                                            \
    (Nó z)                                      [Tio Negro]

Pseudocódigo Totalmente Comentado: RB-INSERT(T, z)

1y = T.nil// Inicia y como a folha sentinela, servirá para guardar o futuro pai de z.
2x = T.root// Começa o cursor x no topo absoluto da raiz da árvore.
3while x != T.nil// Percorre a árvore para encontrar o local correto de inserção binária.
4 y = x// Atualiza y para manter a referência do último nó válido percorrido.
5 if z.key < x.key// Se a chave do novo nó for menor que a chave do nó atual...
6 x = x.left// ...avança a pesquisa para a subárvore esquerda.
7 else x = x.right// Caso contrário, avança a pesquisa para a subárvore direita.
8z.p = y// Assinala oficialmente o nó y como o pai do novo elemento inserido z.
9if y == T.nil// Se a árvore se encontrava vazia (y continua na sentinela inicial)...
10 T.root = z// ...o novo nó z passa a ser a própria raiz principal.
11else if z.key < y.key// Se a árvore não for vazia e z for menor que o seu pai y...
12 y.left = z// ...anexa z como o filho esquerdo do nó pai y.
13else y.right = z// Caso contrário, anexa z como o filho direito do nó pai y.
14z.left = T.nil// Define que o braço esquerdo de z aponta para a folha sentinela.
15z.right = T.nil// Define que o braço direito de z aponta para a folha sentinela.
16z.color = RED// Pinta obrigatoriamente o novo nó de VERMELHO conforme as regras.
17RB-INSERT-FIXUP(T, z)// Invoca os algoritmos de ajuste para rebalancear e corrigir as cores.

Pseudocódigo Totalmente Comentado: RB-INSERT-FIXUP(T, z)

1while z.p.color == RED// O ciclo corre enquanto houver violação de dois nós vermelhos seguidos.
2 if z.p == z.p.p.left// Se o pai de z for o filho esquerdo do avô...
3 y = z.p.p.right// ...atribui o nó y como sendo o tio de z (filho direito do avô).
4 if y.color == RED// [CASO 1]: O tio y é VERMELHO. Faz-se recolorização simples.
5 z.p.color = BLACK// Pinta o pai de z com a cor PRETA.
6 y.color = BLACK// Pinta o tio y com a cor PRETA.
7 z.p.p.color = RED// Pinta o avô de z com a cor VERMELHA.
8 z = z.p.p// Atualiza o ponteiro de foco z para o avô para continuar os testes.
9 else// Se o tio for PRETO, caímos nos casos que requerem rotações físicas.
10 if z == z.p.right// [CASO 2]: Formato Ziguezague (z é filho direito e pai é esquerdo).
11 z = z.p// Passa o ponteiro z para o nó pai.
12 LEFT-ROTATE(T, z)// Executa rotação à esquerda no nó para alinhar em linha reta.
13 z.p.color = BLACK// [CASO 3]: Formato Linha Reta. Altera a cor do pai para PRETO.
14 z.p.p.color = RED// Altera a cor do avô para VERMELHA.
15 RIGHT-ROTATE(T, z.p.p)// Realiza uma rotação à direita aplicada diretamente no avô.
16 else (simétrico)// Bloco espelhado para quando o pai é filho direito do avô.
17T.root.color = BLACK// Garante rigorosamente que a raiz principal da árvore permanece preta.

Remoção: RB-DELETE(T, z) (Slide 25)

Remover nós numa árvore Red-Black exige o uso de uma rotina auxiliar chamada RB-TRANSPLANT(T, u, v) para substituir sub-árvores. Se o nó fisicamente removido ou movido for BLACK, removeu-se uma unidade preta de um caminho, violando a Propriedade 5. Para corrigir, ativa-se o procedimento reparador.

Os 4 Casos do RB-DELETE-FIXUP(T, x) (Slide 26)

O nó substituto x ganha a propriedade conceitual de ser "Preto Extra" (Double-Black). O algoritmo analisa o seu **irmão** w para descarregar este peso preto:

  • Caso 1: O irmão w é RED. Troca-se a cor do pai com w, faz-se uma rotação no pai e o irmão muda, caindo num dos casos seguintes.
  • Caso 2: O irmão w é BLACK e ambos os seus filhos são BLACK. Retira-se o peso preto de w (passa a RED) e o problema do preto extra sobe para o pai (x = x.p).
  • Caso 3: O irmão w é BLACK, o filho esquerdo de w é RED e o direito é BLACK. Faz-se rotação local em w para transformá-lo no Caso 4.
  • Caso 4: O irmão w é BLACK e o seu filho direito é RED. Ajustam-se as cores finais, executa-se uma rotação no pai e o preto extra é absorvido com sucesso, terminando o algoritmo.

Pseudocódigo Totalmente Comentado: RB-DELETE-FIXUP(T, x)

1while x != T.root and x.color == BLACK// Executa enquanto o cursor x não atingir a raiz e continuar duplo-preto.
2 if x == x.p.left// Se o nó x for classificado como o filho esquerdo do seu pai...
3 w = x.p.right// ...atribui a variável w como o irmão de x localizado na direita.
4 if w.color == RED// [CASO 1]: O irmão w tem a cor VERMELHA.
5 w.color = BLACK// Altera a cor do irmão w para PRETO.
6 x.p.color = RED// Altera a cor do pai do nó x para VERMELHO.
7 LEFT-ROTATE(T, x.p)// Realiza uma rotação à esquerda em torno do pai de x.
8 w = x.p.right// Atualiza a nova referência do irmão w após a rotação efetuada.
9 if w.left.color == BLACK and w.right.color == BLACK// [CASO 2]: O irmão w é preto e ambos os seus filhos são pretos.
10 w.color = RED// Retira um nível de preto do irmão alterando a sua cor para VERMELHO.
11 x = x.p// Passa o ponteiro e encargo de duplo-preto para cima, para o nó pai.
12 else// Se os filhos do irmão w não forem ambos pretos...
13 if w.right.color == BLACK// [CASO 3]: O filho direito de w é preto e o esquerdo é vermelho.
14 w.left.color = BLACK// Modifica a cor do filho esquerdo de w para PRETO.
15 w.color = RED// Modifica a cor do próprio irmão w para VERMELHO.
16 RIGHT-ROTATE(T, w)// Efetua uma rotação local para a direita em torno do irmão w.
17 w = x.p.right// Reajusta a referência de w que agora cai obrigatoriamente no Caso 4.
18 w.color = x.p.color// [CASO 4]: O irmão w herda de forma direta a cor atual do pai.
19 x.p.color = BLACK// Força a cor do pai para PRETO.
20 w.right.color = BLACK// Pinta o filho direito de w com a cor PRETA.
21 LEFT-ROTATE(T, x.p)// Remove a discrepância aplicando uma rotação esquerda no pai.
22 x = T.root// Define x como a raiz para quebrar o ciclo while instantaneamente.
23 else (simétrico)// Bloco de código idêntico invertendo left por right de forma espelhada.
24x.color = BLACK// Garante por segurança final que o nó terminal x é pintado de PRETO.
