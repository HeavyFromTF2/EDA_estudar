Sebenta Completa: Aula 8 — Árvores Red-Black

Pesquisa Binária Balanceada, Propriedades Estritas, Rotações e Casos de Ajuste · IPBeja

Porquê Árvores Red-Black? (Slide 2)

As operações básicas numa Árvore de Pesquisa Binária normal demoram O(h), onde h é a altura. Se os dados forem inseridos ordenados, a árvore degenera numa lista ligada gigante com h = n, estragando a eficiência. As árvores **Red-Black** resolvem isto forçando um balanceamento através de atribuição de cores, garantindo tempo O(log n) no pior cenário possível.

As 5 Propriedades Invioláveis (Slide 4)

Uma árvore de pesquisa binária é uma Árvore Red-Black se satisfizer as seguintes propriedades:

1. Cada nó é obrigatoriamente ou RED (Vermelho) ou BLACK (Preto).
2. A Raiz da árvore é sempre BLACK.
3. Todas as folhas vazias (NIL) são sempre BLACK.
4. Se um nó é RED, os seus dois nós filhos têm de ser obrigatoriamente BLACK (Não pode haver dois vermelhos consecutivos verticalmente).
5. Para cada nó, todos os caminhos simples desse nó até às folhas descendentas contêm exatamente o mesmo número de nós BLACK (Altura Negra - black-height).

O Slide 5 demonstra matematicamente que uma árvore red-black com n nós internos tem uma altura máxima de h <= 2 log(n + 1).

Rotações na Árvore (Slide 6 e 7)

As operações de modificação (Inserção/Remoção) alteram a árvore e quebram as propriedades Red-Black. Para repor a ordem sem violar as regras de pesquisa binária (elementos à esquerda menores, à direita maiores), usamos as **Rotações Locais** que alteram os ponteiros de forma instantânea em tempo O(1).

Pseudocódigo Comentado: LEFT-ROTATE(T, x) (Slide 7)

LEFT-ROTATE(T, x)
1  y = x.right            // Define y como o filho direito de x (y vai subir para a posição de x)
2  x.right = y.left       // O filho esquerdo de y passa a ser o novo filho direito de x
3  if y.left != T.nil     // Se a subárvore esquerda de y não for uma folha vazia (sentinela)...
4      y.left.p = x       // ...atualiza o ponteiro do pai dessa subárvore para apontar para x
5  y.p = x.p              // O pai de y passa a ser o antigo pai de x (y assume o lugar na estrutura superior)
6  if x.p == T.nil        // Se x era a raiz original da árvore...
7      T.root = y         // ...então y passa a ser a nova raiz oficial da árvore T
8  else if x == x.p.left  // Caso contrário, se x era o filho esquerdo do pai...
9      x.p.left = y       // ...y passa a ser o filho esquerdo desse pai
10 else x.p.right = y     // Se x era o filho direito, y passa a ser o filho direito desse pai
11 y.left = x             // x desce na árvore e fica posicionado à esquerda de y
12 x.p = y                // Atualiza o pai de x, indicando que agora o seu novo pai é y

A rotação RIGHT-ROTATE(T, y) funciona exatamente de forma simétrica à anterior (Slide 6), invertendo as referências de esquerda e direita.

Inserção Dinâmica: RB-INSERT(T, z) (Slide 10)

Todos os nós entram na árvore usando a lógica padrão de inserção binária, mas com duas particularidades fundamentais: o nó inserido é pintado inicialmente como RED e os seus filhos apontam para a folha sentinela universal T.nil.

O Algoritmo de Ajuste: RB-INSERT-FIXUP(T, z) (Slide 11-14)

Se o pai do nó inserido também for RED, quebrou-se a Propriedade 4. O algoritmo avalia a cor do tio de z para decidir o que fazer. Assumindo que o pai de z é filho esquerdo do avô, temos 3 Casos:

Caso 1: O tio de z é RED (Slide 12)

Ação: Apenas recolorização. O pai e o tio passam a BLACK, e o avô passa a RED. O ponteiro z sobe para o avô (z = z.p.p) para continuar a verificação nos níveis superiores.

Caso 2: O tio de z é BLACK e z é filho da direita (Ziguezague - Slide 13)

Ação: Aplica-se uma LEFT-ROTATE(T, z.p) no pai de z. Isto transforma o ziguezague numa linha reta estável, caindo imediatamente no Caso 3.

Caso 3: O tio de z é BLACK e z é filho da esquerda (Linha Reta - Slide 14)

Ação: O pai passa a BLACK, o avô passa a RED e aplica-se uma RIGHT-ROTATE(T, z.p.p) no avô. A árvore fica perfeitamente balanceada aqui e o ciclo termina.

Remoção: RB-DELETE(T, z) (Slide 25)

Remover nós numa árvore Red-Black exige o uso de uma rotina auxiliar chamada RB-TRANSPLANT(T, u, v) para substituir sub-árvores. Se o nó fisicamente removido ou movido for BLACK, removeu-se uma unidade preta de um caminho, violando a Propriedade 5. Para corrigir, ativa-se o procedimento reparador.

Os 4 Casos do RB-DELETE-FIXUP(T, x) (Slide 26)

O nó substituto x ganha a propriedade conceitual de ser "Preto Extra" (Double-Black). O algoritmo analisa o seu **irmão** w para descarregar este peso preto:

  • Caso 1: O irmão w é RED. Troca-se a cor do pai com w, faz-se uma rotação no pai e o irmão muda, caindo num dos casos seguintes.
  • Caso 2: O irmão w é BLACK e ambos os seus filhos são BLACK. Retira-se o peso preto de w (passa a RED) e o problema do preto extra sobe para o pai (x = x.p).
  • Caso 3: O irmão w é BLACK, o filho esquerdo de w é RED e o direito é BLACK. Faz-se rotação local em w para transformá-lo no Caso 4.
  • Caso 4: O irmão w é BLACK e o seu filho direito é RED. Ajustam-se as cores finais, executa-se uma rotação no pai e o preto extra é absorvido com sucesso, terminando o algoritmo.
