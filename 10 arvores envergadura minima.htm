Problema da Árvore de Envergadura Mínima (Slides 2-5)

Dado um grafo conexo não orientado G = (V, E), onde cada ramo ou ligação (u, v) ∈ E possui um custo/peso associado w(u, v), o objetivo principal é encontrar um subconjunto acíclico (livre de caminhos fechados) T ⊆ E que consiga interligar todos os vértices do grafo gastando o menor peso total possível:

w(T) = ∑ w(u, v) sobre todos os ramos inseridos em T

Aplicações Práticas no Mundo Real (Slide 2)

  • Circuitos Eletrónicos: Minimização do tamanho físico de pistas metálicas de interconexão em microchips.
  • Redes de Distribuição: Planeamento e traçado de canais de condutas de água ou redes de saneamento básico.
  • Infraestruturas Elétricas: Desenho de linhas de alta tensão ligando cidades com o menor custo de cabos possível.

A Abordagem Gulosa / Greedy (Slide 5)

Ambos os algoritmos estudados nesta secção utilizam uma estratégia computacional conhecida como **Gulosa (Greedy)**. A solução final é construída passo a passo, tomando sempre a decisão localmente ideal no momento (escolher o ramo mais barato disponível) com o objetivo de alcançar uma solução globalmente perfeita.

Regra do Ramo Seguro (Safe Edge): Uma aresta é considerada "segura" para expandir a solução atual se, ao ser adicionada ao conjunto estável acumulado, este continuar a ser um subconjunto válido de alguma árvore de envergadura mínima global.

Algoritmo de Kruskal (Slides 6-10)

O algoritmo de Kruskal adota uma abordagem totalmente focada nas **arestas/ramos** do grafo. Ele ignora a estrutura de nós conectados num bloco único no início; em vez disso, começa com todos os nós isolados nas suas próprias "ilhas" (componentes) e vai interligando-os usando estritamente as arestas mais baratas de todo o grafo, desde que essa ligação não crie um ciclo.

Estrutura de Conjuntos Disjuntos / Union-Find (Slide 6)

Para conseguir validar se a adição de uma aresta provoca ou não ciclos em tempo recorde, o algoritmo recorre a três rotinas estruturais:

  • MAKE-SET(v): Aloca e cria um conjunto disjunto individual contendo apenas o nó v.
  • FIND-SET(v): Devolve a identidade do líder/representante único do conjunto a que o nó v pertence. Se dois nós tiverem o mesmo líder, significa que já estão na mesma árvore.
  • UNION(u, v): Funde permanentemente as duas componentes isoladas dos nós u e v numa só.

Pseudocódigo Comentado: MST-KRUSKAL(G, w)

1A = Ø // Inicializa o conjunto final 'A' vazio, que armazenará os ramos da MST
2for each vertex v ∈ G.V // Inicia uma varredura por todos os vértices que existem no grafo
3 MAKE-SET(v) // Cria um conjunto individual disjunto para cada nó. Cada nó é uma árvore
4sort edges of G.E into ↑ order// Ordena TODOS os ramos do grafo de forma crescente pelo seu peso
5for each edge (u, v) ∈ G.E // Percorre sequencialmente a lista ordenada de ramos, do mais barato ao mais caro
6 if FIND-SET(u) != FIND-SET(v)// TESTE DE CICLO: Se os representantes diferem, estão em árvores separadas
7 A = A U {(u, v)} // RAMO SEGURO! Adiciona formalmente a aresta à nossa árvore final
8 UNION(u, v) // Funde os dois conjuntos das pontas num só, conectando as ilhas de vez
9return A // Retorna a árvore que conecta todos os nós com o menor custo: O(E log V)

Algoritmo de Prim (Slides 11-15)

Ao contrário de Kruskal, o algoritmo de Prim foca-se nos **vértices** e faz crescer uma **única árvore centralizada** e contínua. Ele começa num nó raiz qualquer escolhido arbitrariamente e, a cada passo, inspeciona todas as pontes que ligam a árvore atual ao resto do grafo exterior, capturando o nó externo mais próximo (mais barato).

A Fila de Prioridade Mínima (Q)

  • u.key (Chave): Guarda o menor custo conhecido para ligar o nó u à árvore central. Começa como Infinito (∞) para todos, exceto para a raiz que começa com 0.
  • u.π (Pai/Progenitor): Regista o nó que serviu de ponte para pescar o nó u para dentro da árvore definitiva.

Pseudocódigo Comentado: MST-PRIM(G, w, r)

1for each u ∈ G.V // Corre uma preparação inicial por todos os nós existentes no sistema
2 u.key = INF // Inicializa o custo de ligação de todos como Infinito (∞) por segurança
3 u.π = NIL // Limpa e define a ausência de um pai original para todos os vértices
4r.key = 0 // Atribui chave zero à raiz 'r'. Isto força o algoritmo a começar por ela
5Q = G.V // Carrega todos os vértices do grafo para dentro da fila de prioridade mínima 'Q'
6while Q != Ø // Laço principal: enquanto existirem nós soltos fora da nossa árvore única...
7 u = EXTRACT-MIN(Q) // Extrai da fila o nó 'u' com o menor valor de chave ativo. Ele entra na MST
8 for each v ∈ G.Adj[u] // Analisa detalhadamente cada vizinho 'v' que possua uma ligação direta a 'u'
9 if v ∈ Q and w(u,v) < v.key// Validação: Se 'v' está fora da MST E o ramo (u,v) for mais barato que a key de 'v'
10 v.π = u // Atualiza o pai: o nó 'u' passa a ser o Progenitor oficial da ligação a 'v'
11 v.key = w(u, v) // Diminui o custo da chave de 'v' em Q para o peso do novo ramo: O(E log V)
