Problema da Árvore de Envergadura Mínima (Slides 2-5)

Dado um grafo conexo não orientado G = (V, E), onde cada ramo (u, v) ∈ E possui um peso associado w(u, v), o objetivo é encontrar um subconjunto acíclico T ⊆ E que ligue todos os vértices e cujo peso total seja mínimo:

w(T) = ∑ w(u, v) sobre todos os ramos em T

Aplicações Práticas Reais (Slide 2)

  • Minimização da dimensão de interconexões em circuitos eletrónicos.
  • Minimização da extensão de circuitos de distribuição de água ou condutas.
  • Construção e otimização de redes de distribuição de energia elétrica com menor custo.

Abordagem Gulosa (Greedy) (Slide 5)

Os algoritmos que resolvem este problema utilizam uma estratégia gulosa. Uma árvore é construída passo a passo, adicionando ramos a um conjunto estável e seguro A (que representa um subconjunto de uma MST válida).

Regra do Ramo Seguro: Um ramo (u, v) é considerado "seguro" se, e apenas se, ao ser adicionado ao conjunto A, este continua a ser um subconjunto de uma árvore de envergadura mínima.

Algoritmo de Kruskal (Slides 6-10)

O algoritmo de Kruskal foca-se diretamente nos ramos do grafo. Funciona encontrando um ramo de peso mínimo absoluto que une duas árvores distintas pertencentes a uma floresta que cresce até cobrir todo o grafo.

Mecanismo de Conjuntos Disjuntos (Slide 6)

Para gerir o teste de ciclos de forma altamente eficiente, utiliza-se uma estrutura de dados disjunta (Union-Find):

  • MAKE-SET(v): Cria um novo conjunto cujo único membro é o vértice v.
  • FIND-SET(v): Devolve o representante do conjunto ao qual o vértice v pertence atualmente. É usado para testar se dois nós pertencem à mesma árvore (evitando a criação de ciclos).
  • UNION(u, v): Une os conjuntos que contêm os vértices u e v num único conjunto.

Pseudocódigo Totalmente Comentado

MST-KRUSKAL(G, w)
1  A = Ø                      // Linha 1: Inicializa o conjunto A vazio, onde guardaremos os ramos da nossa MST final.
2  for each vertex v in G.V   // Linha 2: Loop para percorrer cada um dos vértices (V) presentes no Grafo (G).
3       MAKE-SET(v)           // Linha 3: Cria um conjunto disjunto individual para o nó 'v'. Cada nó começa isolado na sua própria árvore.
4  sort the edges of G.E into nondecreasing order by weight w
                              // Linha 4: Ordena TODOS os ramos (E) do grafo por ordem crescente (não decrescente) com base nos seus pesos (w).
5  for each edge (u, v) in G.E, taken in nondecreasing order
                              // Linha 5: Loop principal. Avalia cada ramo (u, v) do grafo, seguindo estritamente a ordem crescente de peso.
6       if FIND-SET(u) != FIND-SET(v)
                              // Linha 6: TESTE DE CICLO. Se o representante do nó 'u' for diferente do representante de 'v', não há ciclo.
7           A = A U {(u, v)}  // Linha 7: RAMO SEGURO! Como não gera ciclos, o ramo (u, v) é oficialmente adicionado ao nosso conjunto final A.
8           UNION(u, v)       // Linha 8: Funde os dois conjuntos/árvores num só, indicando que 'u' e 'v' agora fazem parte da mesma componente.
9  return A                   // Linha 9: Fim do algoritmo. Devolve o conjunto A contendo todas as arestas que formam a Árvore de Envergadura Mínima.

Complexidade Computacional: O(E log V) devido à ordenação inicial dos ramos do grafo.

Algoritmo de Prim (Slides 11-15)

O algoritmo de Prim funciona por agregação sucessiva de ramos a uma **árvore única** central que começa a partir de um vértice arbitrário inicial (raiz). A árvore expande-se até capturar todos os vértices do grafo.

Fila de Espera com Prioridade (Slide 11)

  • Todos os vértices que ainda não se encontram inseridos na árvore em crescimento são mantidos numa **fila de prioridade mínima Q**.
  • A chave (v.key) de cada vértice representa o peso mínimo de um ramo que liga o vértice v a qualquer nó que já pertença à árvore. Se não houver ligação, a chave é inicializada com ∞ (Infinito).
  • O atributo v.π guarda o progenitor (pai) do vértice na árvore final.

Pseudocódigo Totalmente Comentado

MST-PRIM(G, w, r)
1  for each u in G.V          // Linha 1: Loop para percorrer todos os vértices (V) do Grafo (G) para fazer a preparação inicial.
2      u.key = INF            // Linha 2: Inicializa o custo/chave de cada nó com Infinito (∞), pois ainda não conhecemos nenhuma ligação à árvore.
3      u.pi = NIL             // Linha 3: Configura o progenitor (π) de cada nó como nulo (NIL), visto que nenhum nó tem pai atribuído ainda.
4  r.key = 0                  // Linha 4: Define a chave do nó raiz 'r' (por exemplo, o nó 'a'). Isto garante que ele será o primeiro a ser extraído.
5  Q = G.V                    // Linha 5: Insere todos os vértices do grafo dentro de uma fila de prioridade mínima Q (onde a prioridade é o valor de 'key').
6  while Q != Ø               // Linha 6: O algoritmo corre enquanto existirem vértices na fila Q (ou seja, nós que ainda não entraram na árvore).
7      u = EXTRACT-MIN(Q)     // Linha 7: Retira de Q o vértice 'u' que possui a menor chave atual. Ele entra oficialmente na estrutura da árvore.
8      for each v in G.Adj[u] // Linha 8: Loop que inspeciona cada um dos vértices vizinhos 'v' que estão adjacentes (ligados diretamente) a 'u'.
9          if v in Q and w(u, v) < v.key
                              // Linha 9: Condição dupla: Se o vizinho 'v' ainda estiver fora da árvore (em Q) E o peso do ramo (u, v) for menor que a chave atual de 'v'.
10            v.pi = u        // Linha 10: ATUALIZAÇÃO DO PAI. O nó 'u' passa a ser o novo progenitor (π) oficial do vértice 'v'.
11            v.key = w(u, v) // Linha 11: ATUALIZAÇÃO DA CHAVE. O custo de 'v' em Q é atualizado para o peso do ramo w(u, v). (Diminui a prioridade em Q).

Complexidade Computacional: O(E log V) se implementado com uma fila de prioridade binária clássica. Pode atingir O(E + V log V) se recorrer a uma estrutura avançada de Fibonacci Heap (Slide 11).
