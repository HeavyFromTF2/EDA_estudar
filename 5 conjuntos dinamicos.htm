Conjuntos Matemáticos vs. Informáticos

Na matemática pura, os conjuntos são estáticos e imutáveis. Em informática a conversa é outra: os algoritmos manipulam dados que mudam a toda a hora, crescendo ou encolhendo conforme os utilizadores adicionam ou removem coisas. A esses conjuntos que variam em tempo de execução chamamos Conjuntos Dinâmicos.

As Duas Categorias de Operações

Qualquer operação que lances sobre uma estrutura de dados recai sempre numa destas duas categorias:

  • Consultas (Queries): São operações de leitura pura. Não alteram rigorosamente nada no conjunto.
    👉 Exemplos: SEARCH(S, k), MINIMUM(S), MAXIMUM(S), SUCCESSOR(S, x) e PREDECESSOR(S, x).
  • Modificações (Modifying Operations): Estas alteram fisicamente o conteúdo ou o tamanho da estrutura em memória.
    👉 Exemplos: INSERT(S, x) e DELETE(S, x).

Dicionários e Elementos Satélite (Termos de Exame)

O que é um Dicionário em EDA? É um conjunto dinâmico que suporta apenas as três operações mais básicas e essenciais: INSERT, DELETE e SEARCH.

Chave vs. Dados Satélite: Geralmente, pesquisamos elementos usando um identificador único chamado Chave (Key). Mas os objetos trazem carga útil atrás deles! Toda a informação extra associada a essa chave chama-se Dados Satélite (Satellite Data). Se precisarmos de mover o elemento, os dados satélite movem-se com a chave.

Pilhas e a Política LIFO (Last-In, First-Out)

Numa pilha (Stack), o último elemento a entrar é obrigatoriamente o primeiro a ser retirado (pensa numa pilha de pratos). O ponteiro crucial aqui chama-se S.top, que guarda o índice do elemento que está mesmo no topo da pilha.

⚠️ Cuidado com as Condições de Limite (Erros de Execução):
• Stack Overflow: Acontece quando tentas empilhar (PUSH) um elemento, mas a tabela já atingiu o limite máximo de tamanho de alocação (S.top > S.length).
• Stack Underflow: Acontece quando tentas desempilhar (POP) um elemento de uma pilha que está completamente vazia (S.top == 0).

Simulador de Pilha com Algoritmos Associados

Brinca com os botões PUSH/POP e vê o ponteiro S.top (Base 1) a deslocar-se a par dos algoritmos teóricos abaixo.

STACK-EMPTY(S)
1 if S.top == 0 // Verifica se o ponteiro de topo está em zero (pilha vazia)
2 return true // Se sim, confirma que está vazia
3 else return false // Caso contrário, ainda há elementos dentro
PUSH(S, x)
1 S.top = S.top + 1 // Avança o ponteiro de topo para abrir espaço
2 S[S.top] = x // Guarda na nova posição
POP(S)
1 if STACK-EMPTY(S) // Verifica se a pilha está vazia antes de tentar retirar
2 error "underflow" // Não há nada para retirar: erro de underflow
3 else S.top = S.top - 1 // Recua o ponteiro, descartando o elemento do topo
4 return S[S.top + 1] // Devolve o elemento que estava no topo

Filas de Espera e a Política FIFO (First-In, First-Out)

Nas filas (Queues), quem chega primeiro é atendido e sai primeiro (como na fila do supermercado). A inserção chama-se ENQUEUE e a remoção chama-se DEQUEUE.

A Magia da Fila Circular

Para não desperdiçarmos memória, a fila do manual do Cormen/IPBeja é **Circular**: quando os ponteiros chegam ao fim do array, eles "dão a volta" e regressam ao índice 1 se houver casas vazias livres.

  • Q.head: Aponta para a cabeça (o próximo elemento a ser removido).
  • Q.tail: Aponta para a cauda (a posição exata onde o próximo elemento **vai entrar**).
Detetores de Erro na Fila:
• Se Q.head == Q.tail, significa que a fila está Vazia. Tentar fazer Dequeue gera Underflow.
• Se Q.head == Q.tail + 1 (ou se Q.head == 1 e Q.tail == Q.length), a fila está completamente Cheia! Tentar fazer Enqueue dá Overflow.

Simulador de Fila Circular

Insere elementos para veres os ponteiros a dar a volta ao array circular (Tamanho fixo = 6 casas).

ENQUEUE(Q, x)
1 Q[Q.tail] = x // Guarda o novo elemento na posição de cauda atual
2 if Q.tail == Q.length // Chegou ao fim do array: precisa de dar a volta
3 Q.tail = 1 // Volta ao início (comportamento circular)
4 else Q.tail = Q.tail + 1 // Avança normalmente para a próxima posição
DEQUEUE(Q)
1 x = Q[Q.head] // Guarda o elemento da cabeça para devolver
2 if Q.head == Q.length // Chegou ao fim do array: precisa de dar a volta
3 Q.head = 1 // Volta ao início (comportamento circular)
4 else Q.head = Q.head + 1 // Avança normalmente para a próxima posição
5 return x // Devolve o elemento removido

Listas Ligadas Duplas

Ao contrário dos arrays ordinais, numa Lista Ligada a ordem dos elementos não vem dada pelos índices da tabela, mas sim por referências de memória (ponteiros). Cada nó é uma estrutura independente com três campos:

  • x.key: O dado propriamente dito.
  • x.next: Ponteiro que salta para o elemento seguinte (vale NIL se for o fim).
  • x.prev: Ponteiro que aponta para o elemento anterior (vale NIL se for o início).

Sentinelas: O Truque Limpa-Código

Para evitar fazer verificações do tipo if x.next == NIL ou if x.prev == NIL a toda a hora (o que enche o código de condições lentas), usamos um objeto especial chamado Sentinela (Sentinel), representado por L.nil.

A sentinela faz o papel de um nó "dummy/fantasma" intermédio que fecha a lista num anel circular. O next do último elemento aponta para a sentinela, e o prev do primeiro elemento aponta também para ela. Com isto, o código de inserção/remoção fica limpo, direto e muito mais rápido!

Simulação de Objetos na Ausência de Ponteiros Reais

Como lidamos com memória em computadores ou linguagens antigas que não gerem ponteiros de forma nativa? O manual aborda duas técnicas:

  • Arrays Múltiplos: Criamos três arrays paralelos (key[x], next[x], prev[x]) onde o mesmo índice x acede às propriedades do mesmo objeto fictício.
  • Array Único Composto: Guardamos tudo sequencialmente num só grande array de inteiros. Cada objeto fictício consome exatamente 3 posições consecutivas de memória (Índice $i$=chave, $i+1$=next, $i+2$=prev).

Lista Livre (Free List): A memória disponível que não está a ser usada por nenhum nó válido não fica ao abandono: é organizada e encadeada numa lista ligada simples própria. Fazer um "new" significa retirar um índice da Free List; apagar um nó significa devolvê-lo para a Free List.

Representação de Árvores n-árias (Descendente Esq., Irmão Dir.)

Numa árvore binária comum, cada nó tem apenas dois apontadores fixos: left e right. Mas e se um pai puder ter 10, 20 ou um número indefinido de filhos? Alocar arrays fixos para cada nó seria um desperdício colossal de RAM.

A Solução Eficiente (Slide 39): Usar a regra de ouro do algoritmo:
1. x.left-child: Aponta única e exclusivamente para o primeiro filho do nó (o mais à esquerda).
2. x.right-sibling: Aponta para o seu irmão gémeo imediato que está logo à sua direita.
Com apenas dois ponteiros por nó conseguimos mapear qualquer árvore complexa do universo gastando exatamente $O(n)$ de memória total estável!
