Representação Estrutural de Grafos (Slides 4-9)

Um grafo é composto por um conjunto de vértices V e ramos/arestas E que estabelecem as ligações entre eles, sendo formalmente designado por G = (V, E). Existem duas formas padronizadas universais de o representar em memória:

1. Listas de Adjacência (Slides 4, 7)

Consiste num array contendo |V| posições indexadas. Cada entrada Adj[u] aponta para uma lista ligada que armazena os vizinhos diretos do vértice u.

  • Espaço em Memória: Ocupa estritamente O(V + E).
  • Ideal para: Grafos Esparsos, nos quais o número real de ramos é muito inferior ao teto máximo teórico (|E| << |V|²).
  • Grafos Ponderados: O custo ou peso do ramo w(u, v) é guardado diretamente como um campo adicional dentro do nó da lista ligada.

2. Matrizes de Adjacência (Slide 8)

Consiste numa matriz quadrada de dimensão fixa |V| × |V|, onde as linhas representam os nós de origem e as colunas os nós de destino.

  • Espaço em Memória: Requer um espaço fixo de Θ(V²).
  • Ideal para: Grafos Densos (|E| ≈ |V|²) ou quando se exige uma verificação instantânea em tempo constante O(1) sobre a existência de ligação entre dois nós.
  • Regra de Atribuição: A[i][j] = 1 caso exista o ramo orientado (i, j), e 0 caso não exista. Para grafos não orientados, a matriz resultante é simétrica em relação à sua diagonal principal.

Matriz de Incidência (Slide 9)

Caso o grafo seja orientado e livre de auto-ciclos, este pode ser mapeado através de uma matriz retangular B de dimensões |V| × |E|:

B[i][j] = -1  // Indica que o ramo j emerge/parte do vértice i
B[i][j] =  1  // Indica que o ramo j incide/chega ao vértice i
B[i][j] =  0  // Indica que o vértice i não faz parte do trajeto do ramo j

Pesquisa com Prioridade à Largura — BFS (Slides 10-14)

A partir de um vértice inicial fonte (s), o algoritmo de Pesquisa em Largura (BFS) expande a sua pesquisa em ondas concêntricas. Ele descobre sistematicamente os nós alcancáveis e garante computar a distância mais curta (número mínimo de ramos) a partir de s. Opera com complexidade temporal linear de O(V + E).

O Mecanismo de Cores e Estados

  • WHITE (Branco): O nó ainda não foi descoberto ou visitado pelo algoritmo.
  • GRAY (Cinzento): O nó já foi descoberto. Representa a fronteira da pesquisa e encontra-se na Fila de espera.
  • BLACK (Preto): O nó e a sua lista de adjacências foram totalmente processados e esgotados.
Algoritmo de Pesquisa

Pseudocódigo Comentado: BFS(G, s)

1for each vertex u ∈ G.V - {s} // Loop para limpar e resetar todos os nós do grafo exceto a origem
2 u.color = WHITE // Define o estado como "não visitado" (Branco)
3 u.d = INF // Define a distância inicial do nó como Infinita
4 u.π = NIL // Define o nó pai/antecessor como nulo
5s.color = GRAY // Marca o nó de origem 's' como descoberto (Cinzento)
6s.d = 0 // A distância do nó de origem para ele próprio é zero
7s.π = NIL // O nó de origem é a raiz, logo não tem pai
8Q = Ø // Cria e inicializa uma fila FIFO (primeiro a entrar, primeiro a sair) vazia
9ENQUEUE(Q, s) // Coloca o nó inicial 's' no fim da fila para ser processado
10while Q != Ø // Enquanto a fila contiver nós para expandir
11 u = DEQUEUE(Q) // Retira o nó 'u' que está na frente da fila
12 for each v ∈ G.Adj[u] // Percorre um a um os nós vizinhos diretamente ligados a 'u'
13 if v.color == WHITE // Se o vizinho 'v' ainda estiver Branco (nunca visitado)
14 v.color = GRAY // Descobre o nó vizinho marcando-o a Cinzento
15 v.d = u.d + 1 // Atualiza a distância: é a distância do pai + 1 aresta
16 v.π = u // Regista que o nó 'u' é o pai do nó 'v'
17 ENQUEUE(Q, v) // Insere este vizinho na fila para analisar os vizinhos dele mais tarde
18 u.color = BLACK // Todos os vizinhos de 'u' foram vistos. Fecha o nó a Preto

Pesquisa com Prioridade à Profundidade — DFS (Slides 15-22)

A Pesquisa em Profundidade (DFS) avança pelos ramos do grafo, "mergulhando" o mais profundamente possível ao longo de caminhos lineares antes de efetuar o mecanismo de retrocesso (backtracking). A sua arquitetura interna baseia-se num comportamento de Pilha (LIFO) via recursividade. A sua complexidade temporal é de Θ(V + E).

Timestamps de Execução: d e f

  • u.d (Discovery Time): O instante exato em que o nó é descoberto e transita de WHITE para GRAY.
  • u.f (Finishing Time): O instante em que a exploração dos seus vizinhos termina e o nó transita de GRAY para BLACK.
Teorema dos Parênteses (Slide 19): Numa execução de DFS, os intervals de tempo [u.d, u.f] encontram-se estruturalmente aninhados. Para quaisquer dois nós distintos u e v, os seus intervals ou são totalmente disjuntos ou encontram-se totalmente contidos um dentro do outro.
Travessia em Profundidade

Pseudocódigo Comentado: DFS(G) e DFS-VISIT(G, u)

1procedure DFS(G) // Procedimento principal para varrer todo o grafo
2 for each vertex u ∈ G.V // Loop para inicializar todos os vértices do sistema
3 u.color = WHITE // Reseta o estado inicial de todos para Branco
4 u.π = NIL // Limpa as ligações de parentesco (sem antecessor)
5 time = 0 // Inicializa o relógio global que conta os passos do algoritmo
6 for each vertex u ∈ G.V // Loop para garantir que mesmo nós isolados ou ilhas são visitados
7 if u.color == WHITE // Se encontrar um nó intocado, inicia uma busca profunda ali
8 DFS-VISIT(G, u) // Dispara a exploração em profundidade a partir desse nó

9procedure DFS-VISIT(G, u) // Rotina recursiva que penetra profundamente no caminho
10 time = time + 1 // Avança o relógio global porque um novo nó foi achado
11 u.d = time // Guarda o tempo de descoberta/entrada no nó 'u'
12 u.color = GRAY // Altera o estado do nó para Cinzento (em exploração)
13 for each v ∈ G.Adj[u] // Examina cada vizinho 'v' que está na lista de adjacências de 'u'
14 if v.color == WHITE // Se o vizinho 'v' for Branco, significa que descobrimos um ramo de árvore
15 v.π = u // Define que o nó 'u' foi o responsável por descobrir o nó 'v'
16 DFS-VISIT(G, v) // Faz uma chamada recursiva (salto) para explorar logo o vizinho 'v'
17 u.color = BLACK // Caminhos esgotados e beco sem saída alcançado. Finaliza o nó
18 time = time + 1 // Avança o relógio global no fecho do nó
19 u.f = time // Regista o tempo de finalização/saída definitiva de 'u'

Ordenação Topológica e Componentes (Slides 23-32)

Conceitos avançados estruturados sobre a execução e propriedades da Pesquisa em Profundidade (DFS).

Ordenação Linear

3. Ordenação Topológica (Slides 23-26)

Aplicável estritamente em DAGs (Grafos Orientados Acíclicos). Ordena linearmente os nós de forma a respeitar precedências de tarefas.

1procedure TOPOLOGICAL-SORT(G) // Algoritmo para ordenar tarefas por ordem de precedência
2 call DFS(G) // Executa o DFS padrão para calcular os tempos de finalização (u.f)
3 // insert into front of list// À medida que cada nó for fechado (Preto), insere-o na frente de uma lista
4 return the linked list // Retorna a lista ligada ordenada (representa a sequência correta de execução)
Componentes Fortes

4. Componentes Fortemente Conexos — SCC (Slides 27-32)

Subconjuntos maximais de vértices numa estrutura orientada onde todos os pares conseguem transitar mutuamente entre si (há caminho de ida e volta).

1procedure STRONGLY-CONNECTED-COMPONENTS(G) // Algoritmo de Kosaraju para achar ilhas isoladas com caminhos bidirecionais
2 call DFS(G) // 1ª Etapa: Corre DFS no grafo original para mapear a topologia global
3 compute G^T // 2ª Etapa: Cria o grafo transposto, invertendo o sentido de todas as setas
4 call DFS(G^T) // 3ª Etapa: Corre DFS no grafo invertido, mas processando os nós por ordem decrescente de u.f
5 // output each tree // Cada árvore independente gerada nesta segunda DFS forma um componente forte (SCC)
