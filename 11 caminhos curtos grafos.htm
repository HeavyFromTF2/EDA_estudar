Como funciona de verdade a Relaxação? (Slides 12-13)

Para qualquer algoritmo de caminhos mais curtos, o grafo orientado guarda duas propriedades dinâmicas em cada vértice v:

  • v.d: A estimativa atual do custo total desde a origem até ao nó. Começa a infinito (∞) porque ainda não conhecemos caminhos.
  • v.π: O nó antecessor imediato (progenitor) que nos levou até lá pelo caminho mais barato descoberto até ao momento.
O Bloco de Decisão Executável:
Quando avaliamos uma aresta que sai de u em direção a v com peso w, fazemos uma pergunta matemática:
Se (Custo acumulado em u + Peso da aresta) for MENOR que (Custo atual registado em v)
Então atualizamos o nó v!

A Função de Inicialização Base

Antes de aplicar qualquer um dos algoritmos, o grafo tem obrigatoriamente de correr uma rotina para limpar dados antigos (INITIALIZE-SINGLE-SOURCE):

INITIALIZE-SINGLE-SOURCE(G, s)
1  for each vertex v in G.V
2      v.d = INFINITY
3      v.π = NIL
4  s.d = 0   // A origem custa zero para chegar a ela própria!

Algoritmo de Dijkstra (Slides 21-24)

É um algoritmo guloso (greedy). Ele escolhe sempre o nó em aberto que tem a menor estimativa de distância acumulada.

Restrição Crítica de Exame: Dijkstra assume obrigatoriamente que as ponderações de todas as arestas são não-negativas (w(u, v) ≥ 0). Se o grafo tiver um peso negativo, o algoritmo falha porque fecha os nós permanentemente impossibilitando a sua reavaliação.

Nota sobre esta simulação: Observe como o Dijkstra falha academicamente neste grafo ao tentar processar as arestas com pesos negativos. Ele fecha o nó T prematuramente e não consegue encontrar o caminho mais curto real que passa por Y.

Pseudocódigo Padrão

DIJKSTRA(G, w, s)
1  INITIALIZE-SINGLE-SOURCE(G, s)
2  S = Ø          // Conjunto de nós com caminho final definitivo fechado
3  Q = G.V        // Fila de prioridade com todos os nós do grafo
4  while Q != Ø
5      u = EXTRACT-MIN(Q)  // Tira o nó com o menor 'd' atual
6      S = S U {u}
7      for each vertex v in G.Adj[u]
8          RELAX(u, v, w)  // Tenta otimizar os vizinhos diretos

Algoritmo de Bellman-Ford (Slides 13-16)

Ao contrário do Dijkstra, o Bellman-Ford é robusto: ele **suporta arestas com pesos negativos**.

Como funciona o mecanismo de repetição?

Em vez de usar uma fila inteligente, ele adota a força bruta organizada: passa por **todas** as arestas do grafo e tenta relaxá-las. Faz este ciclo completo no máximo |V| - 1 vezes. No simulador, adicionámos uma verificação prática: se uma passagem completa não alterar nenhum nó, o algoritmo pode parar mais cedo pois os valores já estabilizaram.

Deteção de Ciclos Negativos

No final das passagens, o algoritmo faz um último varrimento de validação. Se encontrar alguma aresta que **ainda permita reduzir o custo**, significa que existe um ciclo infinito de perda de peso (um ciclo negativo), tornando impossível determinar uma solução estável.

BELLMAN-FORD(G, w, s)
1  INITIALIZE-SINGLE-SOURCE(G, s)
2  for i = 1 to |G.V| - 1
3      for each edge (u, v) in G.E
4          RELAX(u, v, w)
5  for each edge (u, v) in G.E
6      if v.d > u.d + w(u, v)
7          return FALSE  // Detetou Ciclo Negativo! Solução instável.
8  return TRUE
