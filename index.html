Bonus · Resumo Rápido

O que cada coisa é e para que serve, numa frase. Útil para identificar rapidamente diferenças entre algoritmos numa pergunta de exame.

Insertion Sort
Insere cada elemento na posição certa dentro da parte já ordenada. Bom para arrays pequenos ou quase ordenados. O(n²) pior caso, O(n) melhor caso.
Merge Sort
Divide o array ao meio recursivamente e funde as metades já ordenadas. Sempre O(n log n), estável, mas gasta memória extra.
Heap Sort
Usa uma árvore heap para ir buscar sempre o maior elemento. O(n log n) garantido, ordena "no próprio lugar" (in-place), mas não é estável.
Quick Sort
Escolhe um pivô e separa tudo o que é menor/maior que ele. Rápido na prática (O(n log n) médio), mas pode degenerar para O(n²) sem uma boa escolha de pivô (daí a versão aleatorizada).
Notação O / Ω / Θ
O = teto (nunca é pior que isto). Ω = piso (nunca é melhor). Θ = os dois coincidem (comportamento exato).
Teorema Principal
Fórmula pronta para recorrências do tipo T(n) = aT(n/b) + f(n), sem ter de desenhar a árvore de recursão à mão. 3 casos, consoante quem "pesa mais".
Pilhas / Filas / Listas Ligadas
Estruturas base para guardar coleções que crescem/encolhem. Pilha = LIFO (último a entrar, primeiro a sair). Fila = FIFO (primeiro a entrar, primeiro a sair).
Filas de Prioridade
Como uma triagem de hospital: atende sempre o elemento mais "urgente" (maior ou menor chave), não por ordem de chegada. Implementadas com um heap.
Hash Tables
Mapeiam uma chave para uma posição de array através de uma função de dispersão h(k). O(1) esperado; colisões resolvem-se por encadeamento ou endereçamento aberto.
Árvore de Pesquisa Binária (BST)
Cada nó: tudo à esquerda é menor, tudo à direita é maior. Pesquisa/inserção/remoção em O(h) — mas h pode degenerar para n se os dados entrarem já ordenados.
Árvore Red-Black
Uma BST que se auto-equilibra por cores (vermelho/preto), garantindo sempre altura O(log n) — nunca degenera, ao contrário de uma BST simples.
BFS (Largura)
Explora o grafo "por camadas", nível a nível, usando uma fila. Serve para achar o caminho com menos arestas. O(V+E).
DFS (Profundidade)
Explora o mais fundo possível antes de recuar, usando uma pilha (ou recursão). Serve para detetar ciclos e ordenar topologicamente. O(V+E).
Kruskal / Prim (MST)
Ligam todos os nós de um grafo com o custo total mínimo. Kruskal ordena as arestas e vai unindo componentes; Prim cresce a árvore a partir de um nó, sempre pela aresta mais barata disponível.
Dijkstra
Caminho mais curto a partir de uma origem, só funciona com pesos positivos. Usa uma fila de prioridade (min-heap). O((V+E) log V).
Bellman-Ford
Caminho mais curto que aceita pesos negativos e deteta ciclos negativos. Relaxa todas as arestas V-1 vezes. Mais lento que o Dijkstra: O(V·E).
DAG-Shortest-Paths
Quando o grafo não tem ciclos, ordena-se topologicamente e relaxa-se cada aresta uma única vez. Mais rápido que Dijkstra/Bellman-Ford: Θ(V+E).
